# 写作风格档案 v0.2

_三篇工作文章＋一篇硕士毕业致谢 · 2026-11-05 · 区分跨文体习惯、文体规则与单篇观察_

---

## 📋 总画像与版本变化

当前更贴切的总画像是：**从具体事情或材料出发，把原因、影响和自己的判断讲清楚；写技术时偏分析，写关系时偏回忆，允许感情和幽默随语境自然出现。**

三篇工作文章体现“工程实践驱动的解释型技术写作”；致谢补充了回忆、感情、自省与熟人调侃。两者并不矛盾：技术文章通过具体案例解释机制，个人叙事通过具体经历承载感情，都不是只给抽象评价。

本版是整合版，不是对原工作画像的整体推翻。原有详细工作证据保留在[工作写作风格档案 v0.1](<工作写作风格档案_v0.1.md>)。主要修正如下：

| 原工作版中的观察 | v0.2 的归类与修正 |
| --- | --- |
| 从工作问题或学习目的切入 | 保留为工作文体规则，不要求致谢也先提出工作问题 |
| 作者在场，但不以经历为主线 | 仅适用于技术说明；致谢可以由个人经历推动 |
| 英文保留技术精度 | 属于技术文体习惯，不泛化到个人叙事 |
| 明确结论与条件限定 | 技术判断中证据较强；不要求情感表达处处加限定 |
| 层级、清单与流程帮助阅读 | 属于功能性技术排版；致谢以自然段和称呼转场为主 |
| 工程解释是核心文风 | 扩展为一种文体分支；共同基础是具体材料与影响解释 |

本次只补充分析档案，不改写致谢、不训练模型、不制作插件，也不发布原始材料。

### 三个层级

- **跨文体暂定稳定习惯：**在工作文章与致谢之间均有对应证据，可以优先复用，但仍是有限样本观察。
- **文体内较稳定的规则：**在工作材料中反复出现，或与致谢目的直接相关；切换文体时随之调整。
- **单篇特征与待确认偏好：**目前只见于一篇，记录为可选特征，不设为写作硬要求。

这里的“稳定”不是终身不变，也不是统计学置信度。三篇工作文与一篇致谢的样本数量不对称，个人叙事部分的判断尤其需要后续校准。

## 🔍 跨文体的暂定稳定习惯

### 1. 用具体材料支撑评价

工作文章中的具体材料是代码、编译产物、案例与来源；致谢中的具体材料是行动、共同经历和相处细节。

C 从具体输出中指出“看到有一处优化”，再解释代码与指令的对应；D 用“看我流汗时还很体贴地帮我打开空调。”表达关心。两者共同之处不是题材相近，而是让评价有可感知的依据。[C：136–138](<../corpus/derived/异构编程的编译流程（笔记）.md#L136-L138>) [D2](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L21-L25>)

**复用规则：**先找到能够承载判断的具体材料，再表达意义。技术文章不以术语堆砌代替分析，个人文章不以大量形容词代替回忆。材料必须来自实际输入。

### 2. 不只写发生了什么，还写它带来了什么影响

B 通过“这件事情对我们的 Agent 很重要，因为它说明：”把案例带回团队问题；D 则把反复修改论文与能力变化连在一起：

> 就是在这样一来一回的反复修改锤炼当中，我的文章撰写能力有了相当的进步。

工作文章问的是对实现、性能与决策的影响，致谢问的是对能力、心态与成长的影响。这是目前较有支持的跨文体联系。[B：55–61](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L55-L61>) [D1](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L15-L19>)

**复用规则：**重要材料之后，尽量说明“这对当前任务／这对我意味着什么”。不要求每段都写成统一的三步模板。

### 3. 让读者知道作者站在哪里说话

A 的“我认为”、B 的“对我们的转码 Agent”、C 的“我目前仅关注两个内容”，标明经验、关注点或团队视角；D 的“我记得”“我当时”则把叙述放回个人经历，并随着对象切换到“谢谢你们”。[A：49](<../corpus/derived/AMReX开发中的AI助力总结.md#L49>) [B：21](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L21>) [C：378](<../corpus/derived/异构编程的编译流程（笔记）.md#L378>) D 的相关观察来自用户提供的全文。

**复用规则：**保留必要的作者位置，但不机械增加第一人称。写机制可以直接说明，写经验要交代是谁的经验，写感谢可以直接对相关对象说话。

### 4. 允许解释展开，也保留直接表达

工作材料有多层并列、因果和条件组成的较长句子；致谢中也有持续回忆与解释的长段落，同时会用朴素短句收束：

> 往后肯定还有更多的挑战，和你在一起我有信心。

因此，比“全篇短句”更合适的规则是：长句承载需要保留的关系，直接的判断或感情不必再堆修饰。[A：5](<../corpus/derived/AMReX开发中的AI助力总结.md#L5>) [B：21](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L21>) [D5](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L39-L43>)

**复用规则：**优先修复指代不清、因果混乱和重复，而不是按统一字数切句。技术论证保留条件，个人表达保留自然停顿。

### 5. 保留自身认识的范围与变化：中等支持

C 用“我目前仅关注两个内容”交代观察范围，并邀请纠正不准确之处；D 愿意写自己先前“所以想糊弄过去”的想法，再说明受到提醒后的变化。它们共同显示文本会保留“我还在学习或调整”的位置，而非只展示一个完美作者。[C：378–382](<../corpus/derived/异构编程的编译流程（笔记）.md#L378-L382>) [D3](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L27-L31>)

这是两类不同写作行为之间的联系，证据强度低于前几项。适合保留已有的局限和自省，不意味着每篇文章都必须主动暴露缺点或安排“犯错—成长”的故事。

## ⚙️ 工作技术文体：继续保留的规则

以下规则在三篇工作文中有反复证据，但不再统称为所有写作的通用习惯。

### 组织与解释

- **目的先行：**说明当前工作关联或学习收益，再介绍对象。[A：5](<../corpus/derived/AMReX开发中的AI助力总结.md#L5>) [B：7](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L7>) [C：5](<../corpus/derived/异构编程的编译流程（笔记）.md#L5>)
- **分层拆解：**按对象、工作环节、技术层次或中间产物展开，不为了整齐固定凑成三点。[A：9–27](<../corpus/derived/AMReX开发中的AI助力总结.md#L9-L27>) [B：33–39](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L33-L39>)
- **比较有维度：**说清“相似在哪里、差异在哪里、差异怎样影响工作”。近似对应不等于完全等价。[A：21](<../corpus/derived/AMReX开发中的AI助力总结.md#L21>) [C：413–457](<../corpus/derived/异构编程的编译流程（笔记）.md#L413-L457>)
- **机制连接影响：**不要只列功能，继续解释原因和工程后果。[B：43–61](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L43-L61>) [C：657–689](<../corpus/derived/异构编程的编译流程（笔记）.md#L657-L689>)

### 语气与材料

判断可以明确，不必一律弱化；但数字、来源、推断和环境条件要分清。B 的“以上规模与效率数字均为现场展板展示口径。”是这种来源归属的直接例子。[B：167](<../corpus/derived/KubeCon China 2026 参会技术报告.md#L167>)

中文组织叙述，英文保留工具、架构和代码对象。解释优先回答术语在当前问题中做什么，而不是每次都展开百科。标题、列表、表格、箭头和代码用于导航、比较与复现，不是每篇都要齐备的装饰。

“不是……而是……”在会议报告中较突出，可用于校正认识，但不要求致谢或每个技术段落都反复使用。相关详细句式与排版证据见[工作版的句式分析](<工作写作风格档案_v0.1.md#L101-L129>)。

## 💬 致谢与个人叙事：新增的文体分支

本节描述一篇致谢中呈现的个人叙事特征。它们可以作为候选偏好，但尚不代表所有私人写作、博客或回忆文章的稳定规律。

### 1. 感情由具体经历展开

致谢不是只有“感谢指导与帮助”，而是挑选修改论文、照顾讨论时的感受，以及共同活动等具体经历，让感谢有落点。动作细节比感情标签承担更多叙述作用。[D1–D2](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L15-L25>)

**可选组织方式：**发生过什么—对方怎样对待我—这件事怎样影响了我。这个关系可以跨文体复用，但个人文章的“影响”不必转成工作收益或量化结果。

### 2. 经历推动成长，也保留原先的不成熟

文章会写自己原来的想法、得到的提醒和之后的变化，而不是只写结果。这为自省留下了位置。[D3](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L27-L31>)

后续可保留用户已有的不足、犹豫和转变，但不要替用户添加挫折来制造真实感，也不要把每段关系都写成一场人生教育。

### 3. 语气随对象与关系改变

从用户提供的全文看，导师部分较郑重、展开较充分；朋友部分更松弛，有共同生活与运动经历；家人和伴侣部分更直接地表达支持、依赖和信心。第三人称回忆与第二人称感谢会自然切换。

这是一篇内的语体切换，不是全篇必须保持同一种正式程度。未来写给不同对象时，应让具体关系决定语气，而非用一套感谢句平均分配给所有人。

### 4. 轻微调侃是可用资源，不是必选项

> 我个人表示一万个理解，并且早已忘了这件事情。

前文还在清楚回忆朋友打球不传球，接着说已经忘了，形成佯装释然的反差。幽默来自熟人关系，而非脱离上下文的笑话。[D4](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L33-L37>)

只有这一篇提供了明确例子，因此将其记录为“熟人叙事可选语气”，不提升为跨文体稳定规则。正式技术报告无需主动加入调侃，涉及陌生对象时也不要擅自建立亲密口吻。

### 5. 感情可以直接，不必被润色成华丽散文

“和你在一起我有信心”主要依靠日常语言完成情感收束。文中也有“润物细无声”“遮风挡雨”等熟悉比喻，故更准确的观察是“以直接表达为主，允许少量修辞”，而不是“完全没有修辞”。[D5–D6](<../corpus/derived/硕士毕业致谢_风格证据摘录.md#L39-L51>)

仿写时优先保留具体回忆与直白情感，少额外添加意象、排比和总结式金句。熟悉比喻也不自动成为作者专属词库。

## 📊 稳定习惯与文体差异对照

| 维度 | 工作技术文章 | 致谢／个人叙事 | 档案中的归类 |
| --- | --- | --- | --- |
| 判断或感情的支撑 | 代码、案例、来源与观察 | 具体行动与共同经历 | 跨文体暂定稳定 |
| 继续解释影响 | 实现、性能、学习与决策 | 能力、心态、成长与关系 | 跨文体暂定稳定 |
| 作者在场 | 我认为、目前关注、我们的任务 | 我记得、我当时、谢谢你们 | 跨文体存在，强度随文体变化 |
| 句子节奏 | 说明长句配清单与短判断 | 回忆长段配直接情感表达 | 允许展开；不设统一短句指标 |
| 文章入口 | 工作问题或学习目的 | 告别时点与感谢对象 | 文体差异 |
| 组织轴线 | 对象、阶段、技术层次 | 人物关系、经历与回忆 | 文体差异 |
| 对比的作用 | 区分方案、机制与边界 | 部分体现为前后认识变化 | 技术文体内证据更强 |
| 确定程度 | 推断和事实分开，保留条件 | 感谢与承诺可以直接表达 | 文体差异，不生硬互套 |
| 术语与排版 | 英中混排、代码、流程、层级 | 自然段、称呼与叙述转场 | 文体差异 |
| 幽默与自省 | 保留局限，少见明确调侃 | 有熟人调侃与自身不足 | 单篇候选偏好，待更多样本 |

### 从致谢中暂不提炼为个人硬规则的内容

- 感谢对象的排列、导师篇幅较长，以及毕业告别式开头，都与致谢场景有关。
- 密集出现“感谢”“谢谢”主要服务于文章目的，不要求迁移到其他文体。
- 具体人名、称呼、活动、经历和关系属于事实材料，不是可以挪用的风格组件。
- 论文格式、LaTeX 代码、注释、引号方向和偶发措辞不作为仿写目标。
- 不因文章表达感谢，就推断作者具有某种固定人格；不因出现幽默，就要求后续文章都幽默。

## ✍️ 更新后的可复用写作指引

先用共同基础，再按任务选择文体分支。以下是文字指引，不是插件或系统配置。

```text
请参考我的写作风格，但先识别本次文体与读者。

共同基础：从具体材料或经历出发，讲清楚它为什么值得写，以及带来了什么影响。保留必要的作者视角，允许解释展开，避免把所有句子机械切短，也避免用空泛评价代替内容。不要编造实验、数字、人物关系、共同经历或成长故事。

工作技术文章：先交代工作关联或学习目的，按对象、阶段或层次组织。通过对比与具体示例解释机制，再讨论工程影响。区分来源材料、实际观察、个人推断和建议，保留适用条件。中文承担叙述，英文保留必要技术对象，按读者基础补充解释。

致谢或个人叙事：用具体行动和共同经历承载感情，并说明它们怎样影响了自己。允许回忆、直接感谢和认识的变化；根据关系调整郑重或松弛的语气。已有熟人语境时可以保留轻微调侃，但不主动制造笑话或亲密关系。感情可以直白，不必润色成满篇比喻与金句。

不硬套文体：不要把致谢写成任务复盘或收益分析，也不要给技术报告强加抒情结尾。感谢顺序、表格、英文术语、固定对比句和幽默都不是每篇必备。保留事实与自然语感，再修整语病、重复和格式问题。
```

## ✅ 校验清单与后续校准

### 所有文体共用

- [ ] 本次文体和读者已经明确。
- [ ] 重要判断或感情有具体材料承载。
- [ ] 对影响的解释有来由，没有替作者补写经历。
- [ ] “我／我们／你／你们”的位置符合实际叙述关系。
- [ ] 句子与段落的调整服务于理解，而非统一长度。
- [ ] 没有把单篇形式、措辞或技术立场当成永久规则。

### 分支检查

- **工作文：**对比维度、机制、来源与条件清楚；建议与本次任务有关。
- **个人文：**保留真实细节和原有情感强度；称呼与语气符合关系；幽默和自省有材料支持。
- **敏感信息：**不把原文姓名、内部工作信息或具体生活经历默认带入无关任务，不将样本作为插件发布内容。

### 仍待验证

个人叙事目前只有一篇，尚不足以确认幽默、自省、比喻密度、感谢顺序和段落长度是否跨作品重复出现。其他私人文章或可读取的博客正文到来后，应继续区分题材、写作时间和读者影响；目前未把知乎博客当作已读证据。

“初稿＋作者最终修改后的定稿”仍是下一轮较有价值的材料，可帮助识别主动偏好，而不只观察现有成稿。特别需要确认：正式稿保留多少口语、是否倾向保留长句、允许多大幅度重组，以及熟人调侃在其他文章中是否自然出现。

本版最重要的调整是：把“具体材料＋影响解释＋作者视角”作为跨文体基础；把工程拆解、技术术语、致谢语气、人物顺序与熟人幽默放回各自的文体和证据范围。
