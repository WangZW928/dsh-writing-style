# 异构编程的编译流程（笔记）

# 序言

学习编译流程，查看汇编代码，有助于为开发任务提供优化思路。为了方便理解与记忆，本文将SCALE的编译流程与CUDA编译流程，进行类比。

# CUDA编译流程

## 基本编译流程一览：

对`.cu`文件的编译，命令为：`nvcc SrcName.cu -o SrcName`，编译经历了如下流程：

```Bash
SrcName.cu
  ↓
nvcc 前端拆分 host code / device code
  ↓
host 侧生成 .cudafe1.cpp
device 侧生成 .ptx
  ↓
ptxas: .ptx → .cubin
  ↓
fatbinary: .ptx + .cubin → .fatbin.c
  ↓
gcc/g++: 编译 host wrapper + 注册 fatbin
  ↓
nvlink: device link，生成 dlink cubin/fatbin
  ↓
g++: 链接 host object + CUDA runtime
  ↓
SrcName 可执行文件
```

`nvcc -v SrcName.cu -o SrcName` 会打印编译过程的内部调用，其中的一些信息为：

```Bash
cudafe++      CUDA 前端，处理 CUDA 语法
ptxas         PTX assembler，把 PTX 编译成 cubin
fatbinary     把设备代码打包成 fatbin
g++/clang++    编译 CPU host 代码并链接
```

其中，值得观看的文件有两个：PTX 与 SASS 文件。下面以这个代码为例子进行详细的说明：

```C++
#include <cuda_runtime_api.h>
#include <iostream>

__global__ void copyKernel(int *src, int *dst, int size)
{
    const size_t count = 8;
    const int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if(idx >= size)
        return;
    dst[idx] = src[idx];
    for(size_t i = 0;i<count;i++){
        dst[idx] += i;
    }
}

int main()
{
    int *a_dev;
    int *b_dev;
    int *a = new int[1000];
    int *b = new int[1000];
    cudaSetDevice(0);

    cudaMalloc(&a_dev, sizeof(int)*1000);
    cudaMalloc(&b_dev, sizeof(int)*1000);
    cudaMemcpy (a_dev, a, sizeof(int)*1000, cudaMemcpyHostToDevice);
    copyKernel<<<100, 128>>>(a_dev, b_dev, 1000);
    cudaMemcpy (b, b_dev, sizeof(int)*1000, cudaMemcpyDeviceToHost);

    delete[] a;
    delete[] b;

}
```

## PTX 文件

官方文档说明，GPU 编译会经过 PTX 这种中间表示，所以将其理解为面向 NVIDIA 虚拟 GPU 架构的汇编文本，cuda 生成 PTX 的指令为：`nvcc -ptx main.cu -o main.ptx`，其内容为：

```JavaScript
        mov.u32         %r3, %ctaid.x;
        mov.u32         %r4, %ntid.x;
        mov.u32         %r5, %tid.x;
        mad.lo.s32         %r1, %r3, %r4, %r5;
        setp.ge.s32         %p1, %r1, %r2;
        @%p1 bra         $L__BB0_2;

        cvta.to.global.u64         %rd3, %rd2;
        cvta.to.global.u64         %rd4, %rd1;
        mul.wide.s32         %rd5, %r1, 4;
        add.s64         %rd6, %rd4, %rd5;
        add.s64         %rd7, %rd3, %rd5;
        ld.global.u32         %r6, [%rd6];
        add.s32         %r7, %r6, 28;
        st.global.u32         [%rd7], %r7;

$L__BB0_2:
        ret;

}
```

**看到有一处优化**：`add.s32         %r7, %r6, 28;`，该指令将C\+\+程序中的8次 add循环，优化为汇编中的一次add操作。

**注意**，PTX 还不是最终硬件指令。真正接近 GPU 机器指令的是 SASS文件。

# SCALE编译流程

SCALE的这部分内容主要是我根据，工具链PPT，内网指令 \-\-help，AI分析，以及自己试验总结的。如有发现不准确的地方，请及时联系我修改，以免误导。

## 基本编译流程一览：

SCALE的编译流程和 CUDA 编译流程在思想上很接近，只是 CUDA 的 device target 是 NVIDIA GPU，而SCALE 有两个自研 device target：SPU，MPU。

![image\.png](图片和附件/image.png)

如上图，编译流程可以总结为：

```Bash
APE Mixed C/C++
        ↓
     Clang++
        ↓
拆成三路 IR：
    spu.ll
    mpu.ll
    x86.ll
        ↓
分别进入对应 backend：
    SPU Backend → spu.o
    MPU Backend → mpu.o
    X86 Backend → x86.o
        ↓
spu.o + mpu.o 一方面给 Aurora linker → ape.out
spu.o + mpu.o 另一方面给 clang-offload-bundler → fatbin
        ↓
fatbin + x86.o → x86 linker → x86.out
```

与 CUDA 可以进行如下的类比：

部分对应关系可以类比为：

```Bash
CUDA PTX       ≈ SCALE spu.ll / mpu.ll
CUDA SASS/cubin ≈ SCALE  backend 之后的 spu.o / mpu.o
CUDA fatbin    ≈ SCALE  fatbin
CUDA host exe  ≈ SCALE  x86.out
```

# C\+\+代码的编译流程

上面提及了设备端代码的编译过程，现在简要说一下主机端代码（c\+\+）的编译流程，作为学习过程闭环的一部分，在这里用一个极其简单的C\+\+代码示例：

```C++
#ifndef VECTOR_ADD_H
#define VECTOR_ADD_H

#endif
```

```C++
#include "vector_add.h"

void vectorAdd(int* a, int* b, std::size_t n)
{
    for (std::size_t i = 0; i < n; ++i) {
        a[i] = 1;
        b[i] = static_cast<int>(i);
    }

    for (std::size_t i = 0; i < n; ++i) {
        b[i] += a[i];
    }
}
```

```C++
#include "vector_add.h"

#include <cstdio>
#include <memory>

int main()
{
    constexpr std::size_t N = 64;

    auto a_ptr = std::make_unique<int[]>(N);
    auto b_ptr = std::make_unique<int[]>(N);

    vectorAdd(a_ptr.get(), b_ptr.get(), N);

    long long checksum = 0;

    for (std::size_t i = 0; i < N; ++i) {
        checksum += b_ptr[i];
    }

    std::printf("b[0] = %d\n", b_ptr[0]);
    std::printf("b[63] = %d\n", b_ptr[N - 1]);
    std::printf("checksum = %lld\n", checksum);

    return checksum == 2080 ? 0 : 1;
}
```

预处理的内容包括：

1. `#include` 被展开；

2. 宏被替换；

3. 条件编译被处理；

4. 注释通常被删除。

4. 再从栈中读取 `i`； 

5. 计算 `a[i]` 地址； 

6. 读取 `a[i]`； 

7. 又从栈中读取 `i`； 

8. 再次计算 `b[i]` 地址； 

9. 做加法； 

10. 写回结果。 

其中很多地址和变量其实可以保留在寄存器中，不需要反复读取和计算。

但 `-O0` 的目标不是速度，而是：

- 尽量保持源代码结构； 

- 让每个变量都容易被调试器观察； 

- 让源码行和汇编更容易对应。 

在 `-O2` 或 `-O3` 下，编译器会消除大量冗余的栈访问，并使用寄存器和带比例因子的寻址方式实现循环。在满足目标架构、别名分析和数据依赖等条件时，循环还可能被自动向量化。

### `-O0` 和 `-O2` 的本质区别

#### `-O0`

循环变量和参数大量放在栈上：

```Plain Text
a  → 栈
b  → 栈
n  → 栈
i  → 栈
```

每次使用时：

```Plain Text
从栈读取
计算地址
执行操作
再写回栈
```

其特点是：

- 汇编长； 

- 内存访问多； 

- 与源代码结构接近； 

- 方便单步调试； 

- 执行效率较低。 

#### `-O2`

参数和循环变量尽量保存在寄存器中：

```Plain Text
a → rdi
b → rsi
n → rdx
i → rax
```

数组访问直接写成：

```Plain Text
(%rdi,%rax,4)
```

其特点是：

- 不建立传统栈帧； 

- 参数不再先保存到栈； 

- 循环变量保存在寄存器； 

- 数组地址直接使用硬件寻址模式； 

- 删除重复计算和无意义访存； 

- 控制流可能与源码形式不同。

## 汇编：汇编代码到目标文件

汇编器将 `.s` 文件翻译为 可重定位目标文件（`.o`）。目标文件包含机器指令（二进制），但其中的函数调用和全局变量引用的地址还是占位符——因为这些符号可能在别的目标文件中定义，地址要等到链接阶段才能确定。

```C++
g++ -c main.s -o main.o
g++ -c vector_add.s -o vector_add.o
```

这时得到了两个 ELF relocatable object，但还是不能直接运行。可以用 readelf 查看它的内部结构：

```Plain Text
readelf -S main.o        # 查看段（Section）的分布
readelf -s main.o        # 查看符号表（Symbol Table）
objdump -d main.o        # 反汇编代码段
```

## GCC/Clang 扩展

因为函数签名是如下，从标准 C\+\+ 语义上，编译器不能默认认为 `a` 和 `b` 指向互不重叠的内存：

```C++
void vectorAdd(int* a, int* b, std::size_t n);
```

例如调用者理论上可以写：

```C++
vectorAdd(ptr, ptr, N);
```

这会影响循环变换与向量化。可以进行如下的优化：

```C++
void vectorAdd(int* __restrict__ a,
               int* __restrict__ b,
               std::size_t n)
```

`restrict` 相当于程序员向编译器承诺：

> 在这个函数中，`a` 和 `b` 所访问的有效内存区域不会相互重叠。
> 
> 

不过需要明确说明：`restrict` 不是标准 C\+\+ 关键字，而是 GCC/Clang 扩展；承诺错误会导致未定义或不可预测的优化结果。其汇编代码文件（\-O0）为：
